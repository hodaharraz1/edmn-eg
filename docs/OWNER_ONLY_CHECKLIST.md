# قائمة ما على المالك فقط — READY-100

كل بند: الخطوات بالعربي + إزاي تتأكد إنه اشتغل. الكود والسكربتات والتوثيق جاهزة ومستنية القيمة بس. ممنوع أي قيمة حقيقية تتحط في الكود أو issue #7 — كلها env / GitHub Secrets / إعدادات الإدارة.

## 1) أرقام حسابات التحويل الحقيقية (بنك مصر، InstaPay، Vodafone Cash)
- **الخطوات:** من لوحة الإدارة ← إعدادات المدفوعات ← حسابات التسوية: أدخل رقم حساب بنك مصر ورقم InstaPay ورقم محفظة فودافون كاش. أي تعديل يحتاج موافقة شخصين (maker/checker).
- **التأكد:** حوّل 1 جنيه من محفظتك للرقم المُدخل ← الطلب يظهر «قيد المراجعة» ← موظفان يعتمدانه ← الرصيد يزيد، و`reconcile` يطلع صفر فروق.

## 2) حساب SMS (SMS Misr)
- **الخطوات:** خطوات `docs/operations/PUSH_SMS_SETUP.md`: اشترِ باقة، حط `SMS_DRIVER=smsmisr` و`SMS_USERNAME`/`SMS_PASSWORD` في env، و(اختياري) `SMS_FALLBACK_DRIVER`.
- **التأكد:** الخطوة 5 في نفس الدليل: أرسل OTP لرقمك ← يصل خلال ثوانٍ، وسجل الإرسال بلا أخطاء fallback.

## 3) مفاتيح Firebase (FCM) وApple Push (APNs)
- **الخطوات:** `docs/operations/PUSH_SMS_SETUP.md`: أنشئ مشروع Firebase، نزّل مفتاح الخدمة، وحط `FCM_SERVICE_ACCOUNT_B64` (base64)؛ لـiOS: مفتاح APNs من حساب المطور ← `APNS_KEY_B64` + `APNS_KEY_ID` + `APNS_TEAM_ID`.
- **التأكد:** إشعار تجريبي من لوحة الإدارة يوصل لجهازين (أندرويد + iPhone) مثبت عليهم التطبيق من TestFlight/Play الداخلي.

## 4) مفتاح توقيع أندرويد (Upload Key)
- **الخطوات:** `docs/mobile/ANDROID_PLAY.md`: أنشئ الـkeystore محليًا، ارفعه لـPlay App Signing، وحط `ANDROID_KEYSTORE_B64` و`KEYSTORE_PASSWORD` و`KEY_ALIAS` و`KEY_PASSWORD` في أسرار بيئة `play` المحمية على GitHub.
- **التأكد:** workflow `android-play.yml` يبني AAB موقّع ويرفعه للمسار الداخلي، وPlay Console يقبله بلا تحذير توقيع.

## 5) شراء السيرفر
- **الخطوات:** `docs/runbooks/SCALING_10K.md` مرحلة 1: المواصفات والتكلفة التقديرية بالدولار والجنيه (تقدير تصميم مش عرض سعر). انشر staging عليه بدليل INFRA-01.
- **التأكد:** `STAGING_URL=<الرابط> ./scripts/staging-smoke.sh` يعدّي، و`/api/ready` يرجع أخضر.

## 6) موظفان حقيقيان للموافقة المزدوجة
- **الخطوات:** من لوحة الإدارة ← الموظفون: أنشئ حسابين بأدوار مالية (مثل FINANCE_OPERATOR وFINANCE_CHECKER). منح أي دور مالي يحتاج موافقة سوبر أدمن ثاني (SEC-04)، ونفس الشخص ممنوع يكون maker وchecker حتى بحساب تاني (trigger قاعدة البيانات).
- **التأكد:** اعتماد إيداع واحد من الحساب الأول ورفض/قيد من الثاني ← يتم، ومحاولة الحساب الواحد يعمل الاثنين ← تُرفض برسالة واضحة.

## 7) تغيير باسورد قاعدة بيانات staging
- **الخطوات:** غيّر الباسورد في مزود القاعدة، حدّث `DATABASE_URL` في أسرار البيئة، وأعد النشر.
- **التأكد:** `/api/ready` أخضر بعد النشر + smoke targeted يعدّي.

## 8) اختبار اختراق خارجي قبل الإطلاق
- **الخطوات:** تعاقد مع جهة اختبار اختراق، وسلّمها رابط staging (مش الإنتاج) ونطاق الاختبار المكتوب في `docs/security/policy-v1/SECURITY_RELEASE_GATE.md`. ممنوع اختبار ضغط على بيئة مشتركة.
- **التأكد:** تقرير الجهة يصل، وأي نتيجة حرجة/عالية تتقفل قبل قرار الإطلاق.

**بعد ما البنود التمانية تتقفل:** شغّل `npm run test:all` + `flutter analyze` + `flutter test` + smoke الـstaging ← وقتها كل محور ياخد درجته الكاملة والإجمالي يوصل 100% (عدا القانوني، قرارك).
