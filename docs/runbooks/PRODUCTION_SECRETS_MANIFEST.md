# Production secret manifest (names only — no values, nothing generated)

**Rules:**
- Every production secret is **new**. Staging values are refused by fingerprint (`src/server/core/known-nonprod.ts`).
- Generate every secret **on the server**, or on the owner's own machine for keys that must stay offline.
- Never paste a secret into chat, a ticket, git, a shell argument or a log.
- File locations and modes are defined in [PRODUCTION_GO_LIVE.md §2](PRODUCTION_GO_LIVE.md).
- Validate with `scripts/check-production-env.ts`; it prints names only.
- Rotation procedures in detail: [SECRET_ROTATION.md](SECRET_ROTATION.md).

**Generation commands:**

| Command | Produces |
|---|---|
| `openssl rand -base64 48` | ≥ 64 characters |
| `openssl rand -base64 32` | Exactly 32 bytes (encryption key) |
| `openssl rand -base64 36 \| tr -d '/+='` | DB password; URL-safe for connection strings |
| `age-keygen` | Backup key pair |
| `npx web-push generate-vapid-keys` | VAPID pair |

**Tier key:**

| Code | Meaning |
|---|---|
| L | required for **PUBLIC LAUNCH** |
| P | required for **PILOT** |
| R | required for **REAL MONEY** |
| O | optional |

## 2. Database credentials

| Name | Purpose | Generated by | Minimum strength | Stored | Installed in | Rotation | No-downtime | Tier |
|---|---|---|---|---|---|---|---|---|
| `POSTGRES_PASSWORD` (local DB superuser) | Cluster maintenance only; never used by the app | Operator | ≥ 32 | Password manager | `postgres.env` | `ALTER ROLE … PASSWORD`, update the file | YES | L (local DB) |

The init script uses the `*_PASSWORD` values only on an **empty** volume. Later changes are made with `ALTER ROLE`.
