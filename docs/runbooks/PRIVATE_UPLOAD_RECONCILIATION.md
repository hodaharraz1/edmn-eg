# Private local upload reconciliation

The scheduled job is disabled by default. It handles only `STORAGE_DRIVER=local` private objects; database-backed uploads are transactional, and public files are outside this job. Do not run it on a storage root shared by applications that use a different database or bypass the upload service.

Before enabling `PRIVATE_UPLOAD_RECONCILE_ENABLED=true` on the worker, deploy the protected writer to **every** process that can write to the shared local storage, retire all older writers, and wait at least 24 hours. Every worker must use the same PostgreSQL database and the same persistent storage root. This rollout delay protects uploads made by old writers which did not take the new locks. Verify that backups and the existing private-file access and scanning settings are working. Enabling the job is an operational change; this branch does not enable it in any environment.

The hourly job only considers regular private files older than 24 hours with a valid storage key. For each candidate, it obtains nonblocking transaction-scoped writer and metadata locks, checks for **any** `files` row using the key (including soft-deleted rows), and checks the file age again. Busy or referenced files are retained. Before unlinking, it commits an append-only audit attempt containing only a SHA-256 digest of the key, then writes structured attempt/result logs; it never logs file bytes or the original path. If the database or storage is unavailable, the run fails closed and the next scheduled run can retry. Missing files and repeated runs are safe.

Private local uploads hold a metadata lock for their business transaction and a separate database transaction lock during the filesystem write. An aborted business transaction may leave an object, which is eligible only after the grace period. A dead writer releases its locks when PostgreSQL detects the disconnect. The separate lock requires a second database connection while writing; under pool exhaustion the upload can fail and must be retried, rather than bypassing locking. Review pool capacity and monitor the job's failures, duration, storage usage and audit attempts before relying on reconciliation.
