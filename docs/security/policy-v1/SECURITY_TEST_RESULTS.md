**Cookies (من الكود، `src/server/web/session.ts`):** `httpOnly`، و`secure` في البيئات المستضافة، و`sameSite: 'lax'`.

**CSRF:** Server Actions في Next.js تتحقق من تطابق Origin وHost، بالإضافة إلى SameSite=Lax. مسارات الموبايل تستخدم Bearer وليس Cookies.

## 3. الوصول لموارد مستخدم آخر (IDOR / BOLA) — كل مسارات الموبايل التي فيها معرّف

**المنهج:**
- لكل مسار من الـ 81 في `openapi/mobile.v1.json`، يستخدم حساب مهاجم من نفس النوع معرّفًا حقيقيًا يملكه الضحية:
  - عميل ضد عميل: omar ← mona، وmona ← omar في الإرجاع؛
  - طرف خارج الصفقة: mona ← صفقة ahmed؛
  - متجر ضد متجر: homestyle ← techzone وanaqa.
- قبل كل قراءة يُستدعى المالك نفسه كضابط، ويجب أن يحصل على 200. بدونه لا يثبت «غير موجود» شيئًا.
- مسارات الكتابة تُرسل بجسم صالح مولَّد من العقد، أو مكتوب يدويًا للملفات ورقم الموبايل المصري.
- بعدها يُتحقق من قاعدة البيانات أن شيئًا لم يتغير.

**النتيجة:** **0 تسريب و0 تعديل.**

## 6. ما لم يُختبر (ولماذا)

| البند | السبب |
|---|---|
| DAST مثل HawkScan أو ZAP على بيئة مصرح بها | لا يوجد `HAWK_API_KEY`، والفحص الديناميكي على Staging يحتاج تصريحًا |
| اختبار اختراق يدوي مستقل | يحتاج جهة مستقلة. فحص IDOR هنا آلي ومن نفس الفريق |
| إعدادات Vercel وNeon وDNS والحسابات السحابية وMFA عليها | لا وصول من هذه الجلسة |
| استعادة نسخة احتياطية حقيقية من مزوّد قاعدة البيانات (PITR) | يحتاج حساب المزوّد. تمرين الاستعادة المحلي ناجح، لكنه لا يثبت نسخ الإنتاج |
| أمان تطبيق iOS على جهاز | لا يوجد Mac أو iPhone متصل |
| اختبارات MASTG على جهاز Android حقيقي | لا يوجد جهاز متصل. التحقق تم على مستوى الـ APK والكود |
