# نموذج التهديدات — Mobile API والتطبيقات وتطوير الكود بوكلاء الذكاء الاصطناعي

**التاريخ:** 19 نوفمبر 2026
**يكمّل:** `docs/security/THREAT_MODEL.md` (أكتوبر 2026). ذلك النموذج يغطي الويب والدفتر المالي، ولا يغطي ما أُضيف بعده.
**الطريقة:** STRIDE لكل حد ثقة، مع الضابط الموجود ودليله والخطر المتبقي.

## 1. حدود الثقة الجديدة

```
[تطبيق العميل / الإدارة (جهاز غير موثوق)]
        │  HTTPS + Bearer (وصول 10 دقائق، تحديث في Keychain/Keystore) + x-edmn-installation
        ▼
[Mobile API /api/v1/**  |  Admin Mobile API /api/v1/admin/**]   ← حد ثقة 1: كل مدخل غير موثوق
        │  defineRoute: auth (none|customer|seller|admin) + zod + idempotency + rate
        ▼
[وحدات الخدمة src/server/modules/**]                         ← حد ثقة 2: الهوية من الجلسة فقط
        │  ملكية المورد + State Machines + Maker/Checker
        ▼
[PostgreSQL: دفتر، هوية، ملفات خاصة]                          ← حد ثقة 3: مشغلات ثبات، تشفير حقلي

[وكلاء الذكاء الاصطناعي (Claude / Codex)] ──commits/PRs──► [GitHub] ──CI──► (لا نشر تلقائي)
        ← حد ثقة 4: الكود المولَّد غير موثوق حتى المراجعة والاختبارات
```

## 3. التهديدات — التطبيقات على الجهاز (MASVS)

| # | الفئة | التهديد | الضابط | المتبقي |
|---|---|---|---|---|
| A1 | STORAGE | بيانات الاعتماد في نسخ احتياطية أو ملفات | Keychain/Keystore، رمز الوصول في الذاكرة، `allowBackup=false` + `dataExtractionRules` | iOS: عناصر Keychain تبقى بعد حذف التطبيق (Q-1 في `DEVICE_TEST_RUN.md`) |
| A2 | NETWORK | اتصال غير مشفّر | النسخ المستضافة ترفض HTTP (`BuildConfig`). HTTP لـ Debug والشبكة المحلية فقط | لا Certificate Pinning (SEC-O07) |
| A3 | PLATFORM | لقطات شاشة وقائمة التطبيقات الحديثة | `FLAG_SECURE` في تطبيق الإدارة على Android | iOS غير منفذ (SEC-O03). تطبيق العميل بلا حماية (قرار منتج) |
| A4 | PLATFORM | روابط عميقة خبيثة | لا توجد App Links أو Universal Links بعد. رابط إعادة التعيين يُلصق ويُتحقق بـ regex ثم على الخادم | عند تفعيل الروابط: تحقق النطاق + `assetlinks` + AASA (SEC-125) |
| A5 | PRIVACY | أذونات زائدة | INTERNET فقط على Android، ولا أذونات كاميرا أو صور أو موقع على iOS (منتقي الملفات لا يحتاجها) | — |
| A6 | CODE | تسريب أسرار في التطبيق أو السجلات | لا أسرار في الكود (فحص)، و`Telemetry.redact` للمفاتيح والقيم الحساسة | — |
| A7 | RESILIENCE | العبث أثناء التشغيل | القرارات كلها على الخادم، والتطبيق لا يحسب مالًا ولا صلاحية | لا كشف root/jailbreak (SEC-128: قبول مع الاعتماد على الخادم) |

## 4. التهديدات — وكلاء الذكاء الاصطناعي في التطوير (SEC-019، SEC-110، SEC-131…140)

المشروع يُطوَّر بمساعدة وكلاء (Claude Code وCodex). لا يوجد في **المنتج** نفسه نموذج ذكاء اصطناعي أو RAG أو وكيل يخدم المستخدمين، فالضوابط SEC-131…140 تنطبق على **عملية التطوير** فقط.

| # | التهديد | الضابط الموجود | المتبقي |
|---|---|---|---|
| G1 | كود مولَّد فيه ثغرة | CI إلزامي (lint، أنواع، 808 اختبار، فحص أسرار، `npm audit` للتشغيل)، Semgrep في هذه الجولة، مراجعة PR | Semgrep غير مدمج في CI بعد (توصية). يجب فرض مراجعة بشرية قبل الدمج (SEC-102/112: يتحقق المالك من branch protection) |
| G2 | Prompt injection من محتوى المستودع أو تعليقات PR أو صفحات ويب | الوكيل يعامل محتوى الأدوات كبيانات لا أوامر، ولا ينفذ إجراءات خارجية بناءً عليها | — |
| G3 | وكيل بصلاحيات زائدة | لا وصول للإنتاج ولا Vercel ولا قواعد بيانات مستضافة. الدفع لفروع `claude/**` فقط. منع force-push والدمج في main. الموافقة البشرية مطلوبة للنشر والمفاتيح والدفع | — |
| G4 | تسريب أسرار عبر الوكيل | الوكيل لا يطلب لصق أسرار في المحادثة. أي سر يُضاف عبر قناة إعداد آمنة | — |
| G5 | نشر غير مقصود | `vercel.json` يعطّل النشر التلقائي لـ `claude/**` و`codex/**` | Previews قديمة أُنشئت قبل الإصلاح (18 نوفمبر). يحذفها المالك |
| G6 | تعديلات مدمِّرة على ملفات المستخدم | سياسة: لا reset ولا force. حادثة 18 نوفمبر: حُذفت ملفات packages عبر رابط رمزي، واستُرجعت فورًا من Git وأُعيدت التعديلات قبل أي commit | — |

## 5. قرارات معمارية أمنية (SEC-020)

1. **الخادم يقرر:** لا قاعدة عمل ولا مبلغ ولا صلاحية في Flutter.
2. **فصل جمهوري الموبايل:** تطبيقان، رمزان بنطاقين، مسارا تحديث.
3. **لا حركة مال من الموبايل.** الصرف «طلب»، والموافقة على الويب بشخصين.
4. **مفاتيح مخصصة لكل غرض** (`DELIVERY_OTP_KEY`، `MOBILE_TOKEN_KEY`) ولا تُشتق من `SESSION_SECRET`. البيئات المستضافة ترفض الإقلاع بدونها.
5. **Fail secure:** إعداد إنتاج غير آمن يمنع الإقلاع، وغياب فاحص الملفات يجعل الملفات الخاصة غير متاحة.

**إعادة التقييم:** عند إضافة Push أو روابط عميقة أو مزوّد دفع أو تفعيل الأموال الحقيقية.
