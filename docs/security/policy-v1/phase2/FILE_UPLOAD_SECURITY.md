# أمن رفع الملفات

**التاريخ:** 19 نوفمبر 2026

**النطاق:** Marketplace، الصفقة المحمية، الدردشة، الدعم، النزاعات، KYC.

## المسار الموحد

كل رفع يمر عبر `storeUpload` (`src/server/storage/uploads.ts`). لا يوجد مسار رفع آخر (فحص `grep` لكل الوحدات).

| الضابط | التنفيذ |
|---|---|
| نوع المحتوى | فحص البايتات الفعلية (jpeg/png/webp/pdf)، لا الامتداد ولا Content-Type المرسل |
| الامتداد | `ALLOWED_EXT`، والامتداد يجب أن يطابق النوع المكتشف |
| الحجم | صور 8MB، مستندات 10MB (سقف من env). إعداد المدير يخفّض ولا يرفع، والحد الأقصى 25MB |
| معدل الرفع | لكل مستخدم: 400/ساعة لملفات الكتالوج، 60/ساعة للملفات الخاصة |
| الصور العامة | إعادة ترميز بـ sharp: تُزال البيانات الوصفية (EXIF/GPS)، وتُتلف أي حمولة مدمجة |
| الوصول للخاص | لا رابط عام. تحميل عبر مسار مصادَق مع فحص الملكية لكل طلب (اختبارات IDOR في v1.0) |
| فحص البرمجيات الخبيثة | `scanning.ts`. **في الإنتاج: `scanRequired` دائمًا true**، وهي مفروضة في الكود ولا يعطلها `MALWARE_SCAN_REQUIRED=false`. بلا ماسح يبقى الملف QUARANTINED ولا يُقدَّم. لا يُقدَّم إلا CLEAN |

**دليل المرحلة 2:** `tests/unit/upload-scan-gate.test.ts`، 3 اختبارات ناجحة، تثبت أن:
- الإنتاج لا يقدّم UNSCANNED/QUARANTINED/INFECTED حتى مع `MALWARE_SCAN_REQUIRED=false`؛
- الإنتاج بلا ماسح يضع كل رفع في QUARANTINED؛
- INFECTED لا يُقدَّم في أي بيئة.

**النتيجة: لا يمكن تفعيل رفع ملفات غير مفحوصة على الإنتاج بالإعدادات.** هذا يحتاج تعديل كود يمر بمراجعة CODEOWNERS.

## عيب جديد، أُغلق في هذه المرحلة

**SEC-F09:** منتقي الملفات في تطبيق العميل كان يعرض `.heic`، بينما الخادم يرفض HEIC. النتيجة: مستخدم iPhone يختار صورة لا يمكن رفعها أبدًا.
- **الإصلاح:** commit `31d0d47`. القائمة أصبحت دالة واحدة مطابقة للخادم (`pickableExtensions`)، مع اختبار.
- **المتبقي:** تحقق على جهاز iPhone من أن صور الكاميرا الافتراضية (HEIC) تُعرض كـ JPEG أو تُستبعد من الاختيار.
- **تحسين لاحق مقترح (غير منفذ):** تحويل HEIC إلى JPEG على الجهاز قبل الرفع.

## خيارات فحص البرمجيات الخبيثة

**الوضع الحالي في Staging:** لا ماسح.
- الملفات الخاصة تتبع `MALWARE_SCAN_REQUIRED`.
- Staging يعمل على Vercel + Neon، والملفات مخزنة في القاعدة.

> **الأسعار تقريبية للمقارنة فقط**، ويجب التحقق منها من صفحة كل مزود قبل أي قرار. لم أشترك في أي خدمة.

| الخيار | الوصف | التكلفة التقريبية | القيود | الخصوصية |
|---|---|---|---|---|
| **A. ClamAV ذاتي** (موصى به) | **جاهز في المستودع:** `ops/scanner/clamd-http.mjs` + ملف compose (ملف التعريف `scanner`، `clamav/clamav:1.4`، شبكة داخلية). يتوقع `POST /scan` مع Bearer، ويعيد CLEAN/INFECTED/REJECTED | خادم صغير بذاكرة 2–4GB (قاعدة التواقيع تستهلك ~1–1.5GB)، عادة بضعة دولارات إلى ~20$ شهريًا | معدل كشف أقل من المحركات التجارية. يحتاج TLS أمامه (الإنتاج يرفض رابط http للماسح)، وتحديث تواقيع (freshclam)، ومراقبة. **لا يعمل داخل Vercel Functions** | البيانات لا تغادر البنية التحتية: الأنسب لـ KYC |
| B. خدمة سحابية مُدارة (مثل AWS GuardDuty Malware Protection for S3، أو Cloudmersive) | فحص عبر API أو عند الرفع إلى bucket | مجانية بحدود منخفضة، ثم تُحتسب لكل GB أو لكل طلب | يتطلب تخزين كائنات (S3) أو إرسال الملف لطرف ثالث. تكامل جديد = مراجعة جديدة | الملف يُرسل لمزود خارجي: يحتاج تقييم مورد واتفاقية معالجة بيانات، خصوصًا لوثائق الهوية |
| C. خدمات متعددة المحركات العامة (مثل VirusTotal) | | | | **مرفوض:** الملفات المرفوعة قد تصبح متاحة للمشتركين، وهذا غير مقبول لبيانات العملاء |

### خطوات تفعيل الخيار A (عند الموافقة، فهي تتطلب خادمًا مدفوعًا)
1. خادم في منطقة قريبة، ثم `docker compose --profile scanner up -d` من `deploy/compose/docker-compose.prod.yml`، أو حاوية ClamAV + الغلاف خلف وكيل TLS.
2. توليد `SCANNER_TOKEN` (≥32 حرفًا) على الخادم نفسه، ووضعه كـ `MALWARE_SCANNER_TOKEN` في Vercel. لا يمر عبر المحادثة.
3. `MALWARE_SCANNER_URL=https://...` في Vercel.
4. **التحقق** عبر ملف EICAR التجريبي (ملف اختبار قياسي غير ضار):
   - رفعه → INFECTED، لا يُقدَّم؛
   - ملف عادي → CLEAN؛
   - إيقاف الماسح → الرفع يبقى QUARANTINED.
